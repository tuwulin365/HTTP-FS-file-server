# Conventions

## Source of truth

- App version and SDK levels: `app/build.gradle`
- Behavior: Kotlin / web client code
- Public user wording: `docs_ai/user/`
- Prefer this `docs_ai/` tree for public product docs. If the full app repository is present, older notes may also exist under `docs/` — treat them as secondary.

## Docs hygiene (public tree)

- Do **not** commit or paste real signing passwords, private keys, ACME account material, or AdMob unit IDs into documentation.
- Document product behavior and public integration surfaces; avoid step-by-step attack or bypass recipes.
- Prefer “see `ClassName`” over copying sensitive defaults.

## Code

- Free/Pro gates: `UtilsPro` / `ExtendUtils` — avoid duplicating business logic in flavor source sets.
- Match existing style (AppCompat settings UI, existing storage helpers).
- Web UI: build from `client/` then deploy assets; runtime `config.js` is generated by the server.

## Signing

Local `gradle.properties.local` (or equivalent) stays on the signing machine — never in the public docs tree. See [../getting-started/build.md](../getting-started/build.md).
