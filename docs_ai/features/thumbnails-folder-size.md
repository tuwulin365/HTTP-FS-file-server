# Thumbnails and folder sizes

Both are **Client** settings (battery/CPU cost on the phone that hosts the server).

| Setting | Pref (approx.) | Default | Runtime flag in `config.js` |
|---------|----------------|---------|-----------------------------|
| Thumbnails | `battery_thumbnail_key` / `getThumbnailsVal` | on | `use_thumb` |
| Folder sizes | `battery_folder_size_key` / `getFolderSizeVal` | off | `var_can_folder_size` |

Generated by `HtmlBuilder` when serving the web UI.

## Thumbnails

Request via files UI URL query: **`?type=thumb`** on a file path under `/files/…` (`RouteBase`).

- Disabled globally if thumbnails setting is off (or non-image/svg skip paths as coded).
- Images: `MediaUtils.createThumbnail` — scale ~200px, EXIF rotate, PNG; tiny images returned as-is; cache file under `cacheDir`.
- Video: `MediaUtils.createThumbnailVideo` — `ThumbnailUtils` / `MediaMetadataRetriever` frame → PNG ~300px.
- Normal file GET still supports `type=download|text|iframe` for other viewers.

Web UI uses `use_thumb` to decide whether to request thumbs in listing cards.

## Folder sizes

When on, listings recursively sum directory sizes (`FileOperationsUtils.getFolderSizeSuspend`, listing adapters). Expensive on large trees — default off. WebDAV HTML listing may skip recursive sizes even when on; PROPFIND also avoids heavy recursion (see comments in `RouteWebdav`).
